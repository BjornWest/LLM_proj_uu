# Native generation and default basket policy

Fresh `website-world-generation-v1` composition uses the same producer default
basket policy that Runtime already constructs for native footwear worlds when
`basket_shipping.enabled` is omitted or false. An explicit basket fixture is
reused; delivery-admitted plans retain their existing oracle. The default plan
is used only to bind page capabilities and limitations consistently.

This does not enable a new task/grader domain, change the native reference or
request shape, add a basket fixture to old manifests, or update frozen worlds.
Native public policy still comes from the central producer. Synthetic finite
world-factory fixtures without a native commerce schema retain their former
no-commerce projection. Unified v2 dispatch is unchanged.
