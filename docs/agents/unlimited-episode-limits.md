# Prospective ISL-only episode limits

Use `run_episode(..., max_steps=None, max_input_tokens=100_000, ...)` to explicitly disable the total decision/turn ceiling. This opt-in API preserves the finite default of 200 and all positive-integer callers. Unlimited mode requires a positive input-token limit; the existing model-matched complete-request counter runs before each request. A completed final answer is not rejected by a subsequent check. There is no cumulative input/output sum or new total-output ceiling. Per-response output allowances remain separate.

For delegation explicitly use `AgentLimits(total_model_calls=None)` to disable the shared parent/helper model-call cap. The runner rejects unlimited episodes with a finite shared cap instead of silently changing the requested policy. `child_steps=None` also disables an individual helper decision ceiling; helpers still require an input-token limit and retain their finite time deadline. Keep helper concurrency, launch counts and per-tool input bounds as appropriate. None is retained as JSON null in recorded limits, not replaced by a large integer.

Completion, environment termination/truncation, execution errors, ISL, cancellation and checkpoint stops remain active. Transient/correction retry allowances retain their original finite episode/failure-chain rules; absence of a total call ceiling does not grant unlimited retries. Automatic grading declarations and post-close grading are unchanged.

Every launcher must retain finite external wall-time and CPU/memory/process limits, normally through `scripts/run_bounded_job.py` plus `timeout`. The runner's unlimited option is not itself a wall-time watchdog. Existing finite native control drivers, historical plans, accepted frozen releases and CLI defaults stay unchanged. Website owns the separate `saved_answer_lifecycle` validator adoption; Evaluation owns prospective assembled runtime/grade/viewer acceptance. No model rerun is authorized by this source change.
