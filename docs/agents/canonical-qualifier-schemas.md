# Canonical measurement and reference qualifiers

Product owns finite qualifier declarations and native matching; the extractor interprets answer wording. The validator checks the schema, null/evidence consistency and exact nonempty quotes. It does not reinterpret English configuration or measurement claims. Native grading still compares the extracted canonical label with the original public/native reference.

## Measurement basis

`CatalogComparisonGrader` uses `measurement_scopes` already carried by the native task. Only a registered constant declaration or a numeric field's declared basis receives a closed basis vocabulary, plus the unmatched marker and null. For example, a quoted “one shoe in the EU40 reference size” can be mapped by the extractor to the declared “one item, EU 40 reference configuration”. Per-pair, EU42, missing or unrelated context must not be mapped to that label. Facts without a basis keep the literal contract; size context on a mass does not give cushioning a basis.

## Reference configuration

Atomic public-fact tasks can bind a qualifier vocabulary from a source-declared finite table, provided a same-product public assertion identifies the qualifier field. `qualifier_domains.finite_strings` follows unconditional field copies, literal strings, constant/enum declarations and complete weighted-choice value tables. It reads all table members, including those with zero weights in one branch. It never narrows the menu using the sampled model, SKU, stock, task winner, probabilities or private profile values.

This supports the tablet reference bank without parsing formatted reference strings: its two assemblies directly declare their complete configuration labels. Explicit RAM/storage words in a quote can be interpreted as equivalent only when all dimensions and the reference purpose are preserved. A selected LTE/green SKU is not interchangeable with a Wi-Fi/gray reference body. The canonical schema always offers the full declared reference bank, not only the expected target.

Computed expressions, conditional/multiple writers, incomplete tables, alternate case tables, cycles or dynamic choice inputs, undeclared weight keys or another program writing the field retain literal fallback. No probability or physical product sampler is invoked. Product graph/spec/source files are unchanged.

## Binding and acceptance

Atomic tasks with a resolved domain carry its field, version, complete labels and exact inherited declaration SHA-256 pins matched against the world's already-frozen producer source pins in `public_fact.qualifier_declaration`. Native task recreation rejects declaration drift. Declaration-bearing atomic tasks use website-atomic-product-task-v2; literal tasks retain v1. Existing saved tasks remain immutable and run against their frozen source version; new compositions must recreate task/reference through the normal constructor rather than splice metadata into an old task. Consumer source inventories must retain the new `qualifier_domains.py` dependency and exact inherited declaration files. An isolated code commit alone is not the complete evaluation release. The existing H08 media declaration and `_tablets_base.json` are unchanged tracked blobs at the base and tip and are also pinned in the source handoff; callers must retain those assets, not invent a one-target menu or fall back to mutable data.

The shared `semantic_fields` extraction API is still required for canonical comparison bases. Atomic extraction retains its existing exact quote and numeric/unit checks, while its declared qualifier field accepts a schema-valid canonical label even when that label is not verbatim in the quote. Undeclared qualifiers, price reads, other facts, cart state and effect contracts preserve their original behavior. No expected-value refill, unit conversion or new native English parser is introduced.

Tests exercise producer-domain completeness, source drift, quote provenance, missing/unmatched claims and native positive/wrong outcomes. They use explicit formatter claims and synthetic native/capture controls; they are not evidence of model extraction accuracy, actual browser capture, historical regrading or prod readiness. Evaluation owns extractor regressions and prospective complete-source runtime acceptance.

Semantic meaning is extractor-owned: a schema-valid correct canonical label with an unrelated or contradictory exact quote cannot be diagnosed by a mechanical validator alone. Fresh extractor acceptance must include those adversarial cases. Unit tests use explicit supplied matched/unmatched claims and do not prove that the extractor chooses them correctly. Out-of-schema literal claims are contract errors; use the unmatched label for stated values outside the finite menu. A world-pinned declaration that is missing or changed fails closed; worlds without declaration pins keep the literal path regardless of ambient files.
