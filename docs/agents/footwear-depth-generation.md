# Explicit footwear assortment depth

Implemented opt-in world option `footwear_depth` expands distinct model identities
before materializing offers. It leaves default generation and existing frozen public
worlds compatible. This is an authoring recipe, not a claim about market prevalence.

```python
from environments.product_world.scenario import generate_scenario
scenario = generate_scenario(
    task_options={"seed": 0, "family": "footwear", "query": "cheapest",
                  "destination_city": "malmo", "hidden": "none"},
    world_options={"seed": 42, "store_count": 6, "models_per_store": 3,
                   "footwear_depth": {"plausible_models": 10,
                                      "dress_models": 2,
                                      "flip_flop_models": 2,
                                      "size_eu": 40}},
    location_options={},
)
```

The explicit recipe defaults to ten walking/running/hiking models, two dress models
and two flip-flop models. Counts accept 1–20 each; focus size uses the existing EU
size domain. The author must align that size with the intended task; it is not
silently inferred from hidden requirements. Stores are sampled first. Footwear
models are allocated only to stores carrying that family, with shared canonical
models across stores and differing assortments. Every allocated model has a listed
focus-size/black/standard-width variant. This guarantees a listing, not stock.

`attributes.shoe_type` is optional descriptive data, shared across model variants.
It supports explicit structured predicates and product descriptions/filtering; it
is not a product-page control. Size, colour and width remain variant axes. Legacy
products need no new field. New authored types have a one-to-one intended-activity
mapping: walking/running/hiking shoes, formal dress shoes and beach flip-flops.
Contradiction and implication checks use this mapping. Waterproof dress shoes and
flip-flops are outside this initial blueprint vocabulary. Closed-heel rubbing
claims are excluded from flip-flop reviews; absence remains unassessed evidence.

Prices, stock, geographic delivery, review opinions and comparator membership are
sampled independently of success. No rejection sampling, seed search or winner
repair is used. Wider variant review coverage is separately configurable and still
exact-SKU scoped. Public records do not mark a model as a task candidate or distractor.
The current broad shoe task does not forbid dress shoes or flip-flops; those types
must not receive implicit hard exclusions from the oracle or UI.

Frozen example: `.local/coordination/footwear-depth/pin-v1/`, generated by
`.local/coordination/footwear-depth/freeze.py`. It has 14 footwear models among 26
models, 1,632 reports, and four independently sampled comparison memberships.
Eight of the ten walking/running/hiking models have available EU40 offers at or below
1,200 SEK delivered. Review-dependent global status remains uncertain. Publication
is owned by Curation; current URL/evidence belongs in the coordination handoff.
Prior v7 runtime and Qwen manual bank are not rebound by this recipe.

Validation covers type coherence, distinct identity counts, overlapping listings,
focus-size presence, price/stock independence, deterministic generation, legacy
validation and flip-flop narrative scope. No model evaluations were run.
