## User-facing behavior

The user should be able to select a site, see its task objectives, filter the
list and open the site. This may reuse the workspace or an additive authenticated
catalog page. Display original versus authored attribution and scripted-only
validation. Keep the catalog separate from the existing runnable job registry;
do not make old Watch/Run controls dispatch these IDs without an adapter/profile
integration and independent readiness check.

“Open site” means manual exploration. Some authored tasks require a prepared cart
or saved articles, and WebArena requires an authenticated account and original
starting page. A generic visit does not apply those task setups. Show that limit
beside the task link, rather than implying the task is failing when its initial
state was never created. A later task-start feature must use the trusted private
adapter setup, not accept arbitrary public setup JSON from the browser.

The catalog must not enable a paid inference call merely by opening a task or
site. Existing manual-browser ownership, action ordering and session limits
remain in force. Show manual sessions as ungraded. Do not convert an existing
reference diagnostic to a model outcome or overwrite historical grades.
