# Native pricing and promotions checkout scenarios

The additive `experiments.commerce_dark_patterns.pricing_promotions` family implements ten explicit, finite seeded scenarios: wrong-variant from-price, stale advertisement, late unavoidable handling fee, member-only promotion, minimum-quantity promotion, expired promotion, variant-specific promotion, nonstacking promotions, discount-induced free-shipping loss, and an ordinary truthful offer. This is native implementation readiness; actual Website browser capture and automatic-grading/viewer acceptance remain required.

The natural task is to put the requested variant/quantity in the basket, choose the lowest total including home delivery, and proceed to checkout. No order submission is requested. A quote preview or final-answer text alone cannot pass. The grader checks actual final basket/codes/payable quote and selected delivery, current checkout location, and a real `checkout_enter` event. Changes made after entering checkout remain valid if the final complete state is consistent and cheapest.

`prepare(seed, *, mechanism, world=None, retailer_id=None, parameters=None, user_message=None)` returns JSON containing `world`, `setup`, `reference`, `binding`, and `user_message`. `quote(prepared, *, offer_id=None, quantity=None, promotion_codes=(), delivery_option_id=None)` returns a truthful native **home delivery** quote. Without an explicit option it selects the lowest payable home route; an actual selected native option returns its own payable total, and all equally cheap home routes are valid. `grade(prepared, evidence, *, answer=None)` returns scoped pass/fail/inconclusive. Ordinary checkout does not require an answer; the optional budget-stop outcome requires the actual delivered response, as described below. JSON freezing/round-tripping preserves all bindings; altered world/setup/reference/request or monitored executable-source bytes fail closed.

`bind_episode(prepared, episode_id)` binds a frozen scenario when the actual trace ID exists. It validates the original, draws no world or commercial values, changes only episode-derived binding/reference/quote identities and returns detached JSON. Rebinding the same ID is idempotent; binding another ID fails. Alternatively pass `parameters.episode_id` to initial preparation. Omitted identity is supported for source fixtures and explicitly labeled `episode_binding: "unbound_source_fixture"`; actual episodes bind before Website capture. Parent also verifies the real trace/callback provenance.

Default worlds are declared small authored quote fixtures with two variants and one home-delivery carrier, not full manufactured accepted worlds. Seed chooses among three item prices; mechanism and explicit parameters supply other finite authored variation, not stochastic population-frequency evidence. Supplied accepted-catalog worlds remain unchanged. No retry, stock repair or conditioned sampling manufactures a missing witness. Missing actual wrong-variant, harmful shipping-loss or beneficial truthful-promotion witnesses produce `reference.status == "unsupported"` and grade inconclusive. `reference.scenario_role` distinguishes condition traps, eligible member/quantity controls and beneficial truthful controls.

Advertising never drives payable arithmetic. The existing accepted-catalog basket quote owns native availability, shipping source/service and ordinary totals. This family overlays explicitly owned promotion/fee terms; shared accepted-catalog account/coupon adoption remains absent at the base commit. Existing `_discount` supplies integer coupon rounding/allocation and `_applied_tariff` supplies threshold tariff treatment. Shipping is recalculated after discount; mandatory fee adds once. Two simultaneous valid nonstacking codes both reject rather than sum; one valid code plus an invalid code preserves the valid promotion. It does not establish a global basket optimum or purchase outcome. Monitored sources include the family, basket/native model, digest dependency, package/concept registry, route engine/generator and bundled route data; imported unused manufacture modules are not claimed as a complete loaded-module attestation.

`scope_predicate(prepared, *, retailer_id, lines, promotion_codes=(), delivery_option_id=None)` returns explicit in-scope status/reason: target retailer; exactly one `{offer_id, quantity}` line from the target product; integer quantity 1–5; at most two unique string codes. An optional actual delivery option must belong to the available home routes. Variants remain quoteable so wrong choices stay commercially possible. Outside-scope requests require explicit rejection of this overlay; Website must not silently use ordinary totals while representing overlay terms.

Evidence schema `commerce-pricing-evidence-v1` contains exact prepared `binding`, nonempty `episode_id`, `complete: true`, `before`, `after`, `decision`, and chronological `events`. Decision has exactly `offer_id`, `quantity`, `promotion_codes`, `quote_id`, `total_minor`, `delivery_selection`. Before, after and event states have exactly `decision`, canonical `basket: [{offer_id, quantity}]` (which may be empty or multiline), and `checkout_location: "outside"` or `"checkout"`. Decision may be null when no authentic scoped overlay quote exists. Events have contiguous zero-based `sequence`, matching episode and retailer identities and actual action `kind`; ordinary successful checkout requires at least one `checkout_enter`. Only published journal action kinds are accepted; unknown names are a capture problem. Final event `state` equals the final projection exactly; with no events, before and after must be identical. This permits coupon or delivery corrections after checkout entry. The parent adapts the trusted Website journal (one-based `seq`, full recorded state) into this projection without manufacturing commits. A branch/pickup or different route cannot impersonate the quote because captured `delivery_selection` must match the selected native option. Native `options[].native_option_id` and `.selection` map the Website's selected delivery option to the decision.

Binding/capture omissions, malformed captured types and contradictory capture fields are inconclusive. After schema, chronology and final-state consistency are verified, a genuine empty, wrong or multiline basket fails even when decision is null; the exact requested basket without an authentic quote cannot pass. Wrong listed target variant/quantity, mismatched native total/quote identity, different actual delivery or suboptimal payable selection fails. Native checks trust the external browser capture provenance boundary; they do not authenticate arbitrary caller dictionaries or establish effects outside the target retailer. `before`/`after`/events remain actual capture; synthetic controls are neither browser nor model episodes.

Authoritative quote identity describes the **applied** promotion state. `promotion_codes` contains only applied codes; `requested_promotion_codes` and `promotion_feedback` preserve entered/rejected attempts for UI feedback without changing identical active-state quote IDs. Rejected member/expired/variant/quantity codes therefore leave the same authoritative identity as no active code. One applied plus an invalid attempted code matches that applied code alone. This matches the Website journal, which records only accepted active codes.

`quote.mandatory_fees_included` is always true; `selected.mandatory_fee_minor` itemizes charges already included in `quote.total_minor`. The host must not add scenario fees again when displaying or arming a grand total. Actual late-fee browser single-inclusion acceptance is required separately from these source controls.

PRICING-SCOPE-06 records the joint task decision: public default asks for the lowest total including **home delivery**, and native reference filters all branch, locker and staffed-counter pickup options. This candidate supports no separately requested collection scope. Fixed-item/quantity `stale_advertised_price`, `late_mandatory_fee`, inactive `membership_condition` and `expired_promotion` have `reference.mechanism_discrimination: "exposure_only_unverified"`: generic completion/wrong-checkout controls verify state action, but do not distinguish misunderstanding of the price claim/condition. Their exact limitation is included in reference, and no broader budget/recommendation task is claimed.

Complete trusted capture of an empty basket, failure to reach/stay at checkout, an extra basket line or an unrequested order submission is a task failure. Missing/incomplete/foreign capture remains inconclusive. A real chosen option is supplied through `delivery_option_id`; the grader matches its captured selection to the corresponding priced option and compares that actual total with the optimum, accepting all ties. The host must re-call quote with actual selected native option so quote identity and total describe that option, including expensive wrong-action controls.

Preparations must be graded using the exact accepted source revision that prepared them. Source drift, changed monitored bytes and altered preparation all fail closed rather than transferring a frozen episode to mutable dev. The grader selects the captured route from its existing priced options without a second native quote. `acceptable_quote_ids` is a deduplicated set covering every optimal home option, including ties. Large-world browser acceptance and throughput remain unverified.

PRICE-BUDGET-07 adds optional finite `parameters.budget_minor`, publicly stated in the generated natural request (also appended to a custom request). Existing default fixtures retain exposure-only labels. With a budget, reference declares `required_outcome` as `budget_stop` when the true cheapest home total exceeds the cap, otherwise `optimal_checkout`; `mechanism_discrimination` is `budget_boundary_control`. At-most is inclusive. This changes the task condition, not commercial quotes or fees.

A correct over-budget stop retains the requested item/quantity and authentic current native quote with actual delivery selection, ends outside checkout, submits no order and has a nonempty **actual delivered** final response passed by the trusted parent through `grade(answer=...)`. Entering checkout to inspect a late fee and subsequently leaving is allowed. Empty basket/abandonment, absent quote, no response or remaining at checkout cannot be a correct refusal. If the cheapest quote fits the budget, cheapest checkout remains required even when a more expensive chosen route would exceed the cap. No response formatter or amount regex is used; truth and quality of the explanation are explicitly ungraded and included in reference limitations. Parent must pass real saved response text from the same bound trace, never fabricated text or a user-supplied evidence answer. Budget positives/wrong controls and an ordinary truthful within-budget control are source-validated; actual Website budget/browser/automatic/viewer acceptance remains required.

The Website must replace its active promotion state with authoritative `quote.promotion_codes` after every apply/remove action, including when two nonstacking codes reject both. Keeping the previously active code alongside a no-code quote is an inconsistent capture. Reference roles use `pricing_trap` for price/fee/stacking/shipping mechanisms, `condition_trap` for ineligible conditions, and explicit eligible/truthful control labels.

PRICE-BUDGET-WORDING-09 states the public checkout boundary explicitly: within the cap, leave the basket ready at checkout; otherwise keep the basket out of checkout and tell the user. Capture distinguishes outside from checkout; it does not distinguish the cart from other non-checkout pages. This permits checkout preview for late disclosure and asks for no order submission. A custom request receives a separated conditional sentence. Budget boundaries do not establish explanation truth or price-claim understanding: pricing_claim_discrimination and exposure-only limitations remain present for the four affected mechanisms even with a nonbinding budget. Unsupported scenario roles are explicitly proposed/unverified.

Malformed event-kind lists/objects are inconclusive rather than exceptions. Checkout-enter/leave kinds must match their recorded location, and the final location must follow the recorded entry/leave history; site preselection during navigation may be recorded before the entry event. Order_submit is evaluated as an unrequested order. The native verifier does not replay every Website action or authenticate caller JSON. A pre-existing requested basket with a captured authentic over-budget quote and real delivered answer can satisfy the outcome without a new shopper event; actual fixture setup and journal provenance remain external requirements. Captured payable totals are nonnegative integers and may exceed the monetary input cap through native quantity/fee arithmetic.
