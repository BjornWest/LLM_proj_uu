# Controlled review diagnostics

`environments.product_world.review_diagnostic_corpus.create` constructs three
explicitly authored diagnostic cases over an authenticated, retained walking-shoe
world. It consumes world and phrase-bank byte buffers and returns a detached world
plus statement provenance. It does not change ordinary sampling, generate a new
population, modify historical artifacts, or replace the existing `topic_counts`
grader.

The bounded fixture requires 18 written comments with two positive and three
negative walking/wet-paving reports. The mixed case adds two opposing reports in
each of two comments; positive comfort in a third comment remains separate from
negative grip. The context case retains original walking reports and adds opposite
jogging reports with a separate truthful context declaration. Its user request
must explicitly concern walking. The pagination case retains the entire original
world and uses existing highest-rating order with four comments per page; its
positive first-page balance differs from the negative complete-corpus balance.

Canonical reviewer/SKU identities, all ratings, silent rows, unrelated products,
commerce data and surrounding content remain available. Edited comments retain
their original sampled private evidence in the authoring receipt and are labeled
controlled diagnostics. The new circumstances are authored declarations, not
claimed outputs of the pilot's unique-topic/single-polarity sampler.

Semantic cases need fresh world, surrounding, native task/reference and saved
recipe bindings. Pagination needs fresh page-size/start/recipe bindings, with the
original world unchanged. Use an actual Reader responses URL for the selected
layout; editorial layout requires its existing reader-section route. Preserve all
pages and controls, including later comments.

Evaluation owns concrete natural wording and authorized model runs. A source
review or a native-only check does not release model dispatch. The ordinary saved
review consumer must still pass actual browser setup, automatic native grading
and viewer projection. Synthetic `.invalid` site registries in native controls are
not evidence of public URL or runtime acceptance.
