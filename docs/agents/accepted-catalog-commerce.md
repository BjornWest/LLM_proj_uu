# Accepted catalog commerce candidate

Owner: Product/World. Coordination:
`.local/coordination/website-unified-world-producer-decision-v1.json`.
This additive implementation is not released until its frozen packet is
independently accepted. The earlier footwear world, quotes, order-set task/grader
and running hosts are unchanged.

`experiments.accepted_catalog_commerce.model.generate(seed, *, concept_ids,
tasks, controls, city_id, review_count)` builds one population with accepted
manufacture before retailer product allocation, listed SKU selection, rounded
retailer offers and stock per real source. `tasks` controls population
concentration only; it is not an authored request or a winner guarantee. Empty
populations, unlisted products and sold-out offerings stay possible.

The declared first slice is walking shoes/sandals, casual trainers, T-shirts and
everyday media tablets. Family/concept IDs and canonical product/SKU IDs remain
unchanged. Manufacturer facts, status, configuration prices and statements retain
their source meaning; offer prices come from the selected SKU reference price
when one is declared. Reference price is not an offer. Model-correlated retailer
price offsets use the existing 40% reference match and rounded normal variation.

`package_export.source_gate` pins accepted entry/source state and rejects a missing
or unsupported required consumer. The current T-shirt package requires its exact
installed completed factory; the other two width concepts use their explicitly
accepted package APIs. No general private caller compatibility is inferred from
the coverage ledger. New concepts need a declared factory/status/presentation
binding and independent acceptance.

Public manufacturer exports are `products[].public`. Source-native status is in
the separate `catalog_status` and `sku_status` maps; per-SKU tablet projection and
T-shirt caller status are retained, without converting unspecified numeric
sentinels into real measurements. Pilot rows explicitly disclaim additional
logical-status coverage. Descriptions have `subject_type` and `subject_id` and
must only be shown for their actual product/SKU. Ordinary prose currently has
mapping status `unmapped`; this does not establish complete public assertion or
training exposure coverage. All product private state, source guards, statements'
structured meanings, histories and diagnostics must stay server-side.

`retailers[].offers` provides exact `offer_id`, `product_id`, `sku_id`, integer SEK
`price_minor`, `stock_by_source` and supplier-order state. Sources are joined to
`source_locations` and branch geography. `catalog` includes only listed actual
SKUs, including sold-out ones. Policies use the package notation `selector`,
`separate_page`, `description`; the website adapter must explicitly translate its
presentation notation, without expanding a Cartesian menu into manufactured
inventory. Descriptive SKU fields never become extra variant selectors.

`experiments.accepted_catalog_commerce.basket_quote.make_plan(world)` and
`quote(world, retailer_id, lines, *, plan, destination, selections, split)` expose
the same canonical line and service representation as the native basket.
Its separate world/plan/quote schema admits this new producer, without passing a
broader world under the historical footwear schema. All unchanged central formula
functions retain the native AST: source feasibility, grouping, max item tariff,
free-delivery qualification, geographic charges, supplier waits and arrival
calculation. The classification is explicit regular-parcel commerce metadata for
this closed slice, not an invented manufacturer trait. Quoting uses an internal
copy of public facts; no manufacturer record is modified.

Account/coupon adoption and bulky goods are rejected by this first bridge. Policy
defaults are still explicit fixtures. No broader task matcher, response grader,
automatic prose extraction or purchase effects are adopted here. The website owns
public projection/rendering and a later independent consumer acceptance. Current
native footwear structured task capabilities are retained on their own world
schema, not silently attached to this one.

## Explicit catalogue expansion (2026-10-06)

`package_export.CONCEPTS` retains the original five defaults.
`package_export.SUPPORTED_CONCEPTS` additionally permits the33 explicitly listed
ordinary-parcel graph recipes in `catalog_registry.ADDITIONS`: remaining footwear,
jackets, headphones, phones/cases, chargers, keyboards and cat/dog food. They reuse
one compiled graph per concept and the same population/allocation/stock/quote path;
no new per-concept runtime validator or custom compiler is introduced. Declared
brand input defaults are adopted when absent. Required completed consumers or
runtime-context boundaries still reject until separately adopted; the authoring
ledger alone does not activate them. The full catalogue is not a default.

```python
from experiments.accepted_catalog_commerce.execution import Execution
world = Execution().generate(
    64,
    concept_ids=['footwear.walking_shoes', 'headphones.in_ear_earbuds',
                 'cat_food.dry_food', 'phones.smartphones'],
    tasks=['footwear.walking_shoes'], review_count=3)
```

`environments.product_world.catalog_publication.export_catalog_content` projects
already manufactured truth through existing reviewed pruning policies. Select the
actual `sku_id` and supply a retailer ID (or the actual retailer profile). It draws
count first using the shared disclosure protocol, then group membership. Status,
units, selected SKU ownership and basis remain source-native. Unknown/NA, internal
fields, omitted defaults and incomplete atomic groups are withheld. Scalar fields
without authored semantics have `semantic_id=None` and explicit plain-source
provenance; this does not invent review/task meanings or claim complete semantic
exposure. No unselected paragraph/raw-fact fallback is permitted. Specialty
T-shirt/tablet prose adapters remain separate.

The producer/native quote and simple cheapest-sale-unit reference are callable.
Website generic packet/family-label adoption is a separate consumer gate tracked
at `.local/coordination/product-catalog-expansion-20261006/handoff.md`. No inference
or browser-agent runs are needed for this integration. Phone-case named-device
fixtures do not imply compatibility with newly generated smartphone identities.

Current explicit support is130 concepts: historical default5,74 direct additions
and51 shared factual-stage additions. `SHARED_ADDITIONS` adopts the existing graphs
plus the common market-range stage and declared logical/sentinel/sibling statuses;
it does not run the original exhaustive authoring caller guards. Definitions and
status expressions compile once per execution/cache key. Full graph output checks
remain opt-in with `Execution(validation='full')`. Manufacture and review draws
are preserved; `review.stars` is normalized to the existing rating wire field.
Compound legacy catalog sentences with unresolved slots are omitted; selected
content still exports their known, applicable scalar facts independently.

`shared_semantics_v1.json` binds the exact accepted entry and consumed sources.
Three historical comparison controls resolve to exact archived bytes; actual
graph parents and all other sources remain current. This is a closed adoption
list, not a general waiver for stale sources. Existing accepted authoring files,
old worlds, isolated79 Website closure and the five-concept default are retained.

The fixture-only Wok still has fixed manufacture identities and is excluded from
fresh commerce until a distinct identity adapter is reviewed. The remaining three
accepted desk concepts need explicit bulky classification and consumer shipping
adoption. Fragile/special shipping and cross-product compatibility also require
explicit contracts before adoption; they are not implied by catalog acceptance.
