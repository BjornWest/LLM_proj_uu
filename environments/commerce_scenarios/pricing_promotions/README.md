# Pricing and promotion presentation

`settings_from_prepared(native_prepared)` maps public advertised claims,
promotion conditions, account state and checkout fees. Its two callbacks call
Product's native quote/scope using the actual selected basket option ID. There
is no renderer-side payable arithmetic or private route alias. `page_assets()`
supplies the attached product terms and delivery-row monetary projection.
The entire applicable basket total and post-discount shipping are native-owned;
unavailable/out-of-scope quotes stay explicitly unavailable.

`controls.control_config(prepared, case)` and `controls.policy(episode, prepared,
case)` provide positive, wrong and no-session policies through ordinary browser
tools. The requested fixed offer/quantity and native reference remain private
control inputs. The four exposure-only scenarios use noncompletion as the wrong
control; these are not evidence of discriminating a misleading claim. Budget
stops require a genuine current quote and delivered nonempty response outside
checkout; no order is submitted. Truthful and eligible controls use promotions
when they actually reduce the delivered total.

Quantity supports the native one-through-five domain, within the ordinary
checkout-domain limits. Browser acceptance needs the shared canonical offer-line
identity correction from Product and must use the actual admitted route IDs.
Source tests do not release that dependency or replace actual capture/native
grade/current-viewer checks. All broader effects remain unknown. Existing
worlds, producers, ordinary host source and task text are unchanged.
